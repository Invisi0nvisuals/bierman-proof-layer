# Build Notes
## Bierman Autism Centers — Proof Layer

**Last updated:** May 2026

---

## Framework

The proof layer is built on React 19 with Vite as the build tool, TypeScript for type safety, Tailwind CSS 4 for styling, and shadcn/ui for component primitives. The application is a single-page React application (SPA) with client-side routing via Wouter. There is no server-side rendering, no API layer, and no database.

This is intentional. The proof layer is a static frontend demonstration. Its purpose is to validate schema architecture, Rich Results eligibility, and page design — not to demonstrate backend infrastructure.

## Key Architecture Decisions

**Schema in `index.html`, not in React components.** All JSON-LD is in a single `<script type="application/ld+json">` tag in `client/index.html`. This ensures the schema is present in the initial HTML response, not injected by JavaScript after page load. Google can read JSON-LD from both locations, but `index.html` placement is more reliable for crawlers that do not execute JavaScript.

**No microdata attributes in React components.** The `GBPReviewCard` component previously had `itemScope`/`itemType`/`itemProp` microdata attributes. These were removed in v17 because they created a second set of Review nodes that conflicted with the JSON-LD. JSON-LD is the sole schema source.

**`LOCATION` constant as data model.** All location-specific values are isolated in a `LOCATION` constant at the top of `Home.tsx`. This makes the page trivially replicable to new locations — update the constant, and the entire page (content, schema, CTAs, map embed) updates automatically.

**Assets on Manus CDN.** All images are served from Manus CDN paths (`/manus-storage/`). No local binary assets are stored in the project directory. This prevents deployment timeouts caused by large asset files.

## Components

The proof layer uses a minimal component set. Most of the page is implemented directly in `Home.tsx` for simplicity. The key custom components are:

**`GBPReviewCard`** — A native HTML/CSS React component that renders a single GBP review. Props: `reviewer` (name), `rating` (1–5), `body` (review text), `date` (optional). Features: colored initials avatar, SVG polygon gold stars, 160-char truncation with "Read more" toggle, "Posted on Google" badge.

**`GBPReviewGrid`** — Wraps `GBPReviewCard` components in a featured + grid layout. The first review is displayed as a featured card in a left column; the remaining reviews are in a 2-column right grid.

**`DismissBtn`** — A dismissible proof-layer safety banner using `sessionStorage` to persist the dismissed state across page refreshes within the same session.

## Asset Paths

All assets use Manus CDN paths in the format `/manus-storage/{filename}_{hash}.{ext}`. The hash is generated by the Manus CDN upload process and is stable — the same file will always produce the same hash.

To add a new asset:
1. Upload the file using `manus-upload-file --webdev path/to/file.png`
2. Copy the returned CDN path
3. Add the path to the `ASSETS` constant in `Home.tsx`
4. Reference the asset via `ASSETS.{key}` in the JSX

Do not use relative paths, `public/` paths, or `src/assets/` paths for images. All images must be on the CDN.

## Schema Generation

Schema is hand-authored JSON-LD in `client/index.html`. There is no schema generation library or build-time schema compilation. This is intentional for the proof layer — hand-authored schema is easier to inspect, debug, and validate.

For a production implementation with 33+ locations, schema generation should be automated. The recommended approach is a TypeScript function that takes a `LOCATION` object and returns a JSON-LD `@graph` array. This function can be called at build time (for static generation) or at request time (for SSR).

A scaffold for this function is documented in `DATA_MODEL.md`. The function signature would be:

```typescript
function buildLocationSchema(location: LocationData): SchemaGraph {
  // Returns a 26-node @graph array
}
```

## Routing

The proof layer uses Wouter for client-side routing. Currently, there is only one route: `/` (the Ramsey location page). When additional location pages are added, each will be a separate route: `/piscataway/`, `/west-orange/`, etc.

---

## Environment Behavior

The proof layer has no environment variables, no API keys, and no server-side configuration. It is a purely static frontend. The Manus CDN paths are hardcoded in the `ASSETS` constant.

The proof-layer safety banner reads `sessionStorage` to determine whether it has been dismissed. This is the only browser storage used by the application.

## Deployment Notes

Deployment is managed via the Manus platform. The proof layer is deployed to `bierman-proof-layer.manus.space`. Do not deploy to `biermanautism.com` without explicit Bierman approval and a confirmed migration plan.

To deploy a new version:
1. Make changes in the development environment
2. Run `npx tsc --noEmit` to confirm TypeScript is clean
3. Save a checkpoint via the Manus UI or `webdev_save_checkpoint`
4. Click "Publish" in the Manus Management UI

## Known Technical Compromises

**Single-page application for a multi-location system.** The proof layer is a single SPA page. A production implementation would use a multi-page architecture (one page per location) with server-side rendering or static site generation for SEO performance.

**Hand-authored schema.** Schema is hand-authored JSON-LD. A production implementation would use a schema generation function to ensure consistency across all locations.

**No CMS.** Location data is hardcoded in the `LOCATION` constant. A production implementation would use a headless CMS or database to manage location data.

**No internal linking between location pages.** The proof layer links to biermanautism.com location pages for nearby locations. A production implementation would link between pages within the same domain.

**Facebook Sharing Debugger 403.** The Manus CDN blocks `facebookexternalhit` at the infrastructure level. This resolves automatically on custom domain deployment. The OG tags are correct in the HTML.
